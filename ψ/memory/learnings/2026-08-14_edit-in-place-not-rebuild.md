# Lesson: แก้ในไฟล์เดิม ไม่รื้อสร้างใหม่ (เมื่อ user ลงแรงแล้ว)

**Date**: 2026-08-14
**Context**: EXAT pitch deck (Google Slides) — DewS วางรูป/คลิปในไฟล์เดิมไปเยอะ

## Pattern
เมื่อ user ลงแรงวางเนื้อหา/รูป/คลิปในไฟล์ไปแล้ว **ห้ามสร้างไฟล์ใหม่** เพื่อแก้ปัญหาโครงสร้าง — ให้แก้ในไฟล์เดิม
- Google Slides API: `replaceAllText` (แก้ข้อความ), `deleteObject`/`createShape` (แก้ layout), `createImage` (ฝังรูปผ่าน Drive URL) — ทั้งหมดแก้ได้โดยไม่แตะ object ที่ user วางไว้
- ถามตัวเองก่อนเสมอ: "แก้ในที่เดิมได้ไหม" ก่อนรีบิลด์
- DewS หงุดหงิดชัดเจนตอนต้องแทรกรูปซ้ำ ("ทำไมไม่แก้จากของเดิม")

## Related
- โฟกัสงานเสนอราคา/ม้อคอัพ: อ่านเอกสารต้นทาง (TOR) ก่อนวางกลยุทธ์ — เด็คถูกให้คะแนนตามเกณฑ์
- Structural change ควร propose ก่อน build (อย่า build ล่วงหน้าจน deck บวม)
- Requirement กำกวม → ถาม ไม่เดา (case "สามคน" → เดาตัดมณีผิด)
