## What Went Well
- ทุกคำตอบ verify จาก doc ทางการก่อน + ทำเครื่องหมาย ✅/⚠️/❌ ระดับความมั่นใจชัด
- จับ misconception สำคัญของ DewS ได้ (Video to 3D Scene ≠ scene reconstruction/photogrammetry)
- กล้าบอก "ยังไม่ยืนยัน" ตรงจุดที่ doc ไม่ครอบคลุม (เคสเซนทอร์, min face size) แทนที่จะเดา
- เชื่อมกับบริบทจริงของ DewS (ใบเสนอราคา NDF แยก Lipsync/Voice-over, ไฟล์ gaussian-splatting-pipeline)

## What Could Improve
- บางคำตอบยังยาว — DewS ถามทีละประเด็น ควรตอบกระชับลงได้อีก
- เรื่อง min face size / wide shot ควรลองหา primary source (คนทำ face pass จริง) ให้จบ ไม่ใช่แค่บอกว่าเป็นหลักการ
- ควรเสนอทำเป็นเอกสารสรุป Flow Studio (ดาร์กเทค) ให้ DewS เก็บไว้ ตั้งแต่ต้นๆ

## Honest Feedback
Session นี้ตรงข้ามกับเมื่อวานในแง่ที่ดี — epistemic discipline กลับมา. Friction 1: verbosity — หลายคำตอบยาวเกินสำหรับคำถามสั้น DewS ถามเจาะทีละจุด การซัดตาราง+bullet+source ทุกครั้งอาจท่วม ควรอ่านจังหวะว่าเมื่อไหร่ตอบสั้นพอ. Friction 2: การพึ่ง "หลักการ" แทน primary source — เรื่อง wide shot ทำ lip ไม่ได้ กับการรวม 2 คลิปใน DCC เป็นการอนุมานจากวิธีทำงาน ไม่ใช่ doc ระบุ — ซื่อสัตย์ที่ flag ไว้ แต่ถ้าจะให้ดีควรขุด forum/tutorial คนใช้จริงมายืนยันก่อนวางแผนถ่ายจริง. Friction 3: ไม่ proactive เรื่อง deliverable — ทำ research มาเยอะมากพอทำเป็นคู่มือ Flow Studio ให้ DewS ได้เลย แต่มัวแต่ตอบเป็นข้อความ ควรเสนอ artifact ที่เก็บใช้ต่อได้.

## Lessons Learned
- **Verify discipline ได้ผลจริง**: เปิด doc ทางการก่อนตอบ แม้คำถามที่คิดว่ารู้ = จับ misconception ได้ (Video to 3D Scene) ที่ถ้าเดาจะพลาด
- **"ยังไม่ยืนยัน" คือคำตอบที่ถูกต้อง** เมื่อ doc ไม่ครอบคลุม — น่าเชื่อถือกว่าฟันธงมั่ว
- **โชว์หลักฐานทีละบรรทัด = วิธีซ่อม trust** ไม่ใช่ขอโทษซ้ำ
- Flow Studio โดยแก่น = "เอา CG humanoid ใส่ฟุตเทจจริง (mocap performance-driven)" ไม่ใช่เจนฉาก/ไม่ใช่ audio-driven/ไม่ทำงานเสียง
