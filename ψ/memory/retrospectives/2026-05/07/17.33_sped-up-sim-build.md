**Friction 1 — Two sync pushes** เพราะลืม re-sync memory ก่อน commit แรก: เป็น process bug ที่ไม่ควรเกิด /sync push protocol ควรมี step "re-copy global-memory" ก่อน git add เสมอ ไม่ใช่แค่ตอนเริ่ม session ครั้งหน้าจะ check workflow นี้ — ถ้า memory เพิ่งแก้ใน session เดียวกัน ต้องบอก protocol ว่า "always re-copy before commit"

**Friction 2 — TVOC prompt frequency อาจถี่เกินสำหรับ workshop**: ปัจจุบันถาม TVOC ทุก 5 sim-min = 23 prompts ตลอด session ที่ 30x speed (4.5 นาทีจริง) มี 23 popups เด้ง = ผู้ใช้กดถี่มาก อาจรู้สึกล้า — แต่ DewS ยังไม่ทดสอบ ถ้า rehearsal แล้วล้า ก็แก้ตรง constant ได้ตรง ๆ เพิ่ม guard "skip all"

**Friction 3 — เพิ่มสเตปเซสชั่น defer ไว้** เพราะ น้อง มี implementation ที่ยังไม่ push: ฉันตั้งใจถามตำแหน่งก่อนเดา (ดี) แต่ DewS เปลี่ยน topic ไปดู demo ก่อน — งานนี้จึงค้างอยู่ที่ น้อง ครั้งหน้าควร flag ก่อนปิด session ว่า "อย่าลืม sync push ของ น้อง ก่อนกลับมาที่ พี่"

## Lessons Learned

1. **Memory edits mid-session ต้อง re-sync ก่อน commit** — `/sync push` skill protocol ควรมี implicit re-copy step
