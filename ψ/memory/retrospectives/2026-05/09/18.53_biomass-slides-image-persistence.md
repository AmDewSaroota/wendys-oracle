## Honest Feedback

**1. async over localStorage โดยไม่ verify root cause ก่อน**
ตัดสินใจเปลี่ยนเป็น IndexedDB เพราะสมมติว่า quota เป็นสาเหตุ — แต่ไม่ได้ตรวจจริงว่าคือเหตุผลไหน ผลคือ break slides ทั้งหมด ควร debug ก่อน: console.log quota error จริงหรือเปล่า, หรือปัญหา key mismatch? วิธีแก้ที่ conservative กว่า (ตรวจ setStore error แล้วแสดง toast) น่าจะ safe กว่า

**2. ไม่ถาม slot-to-image mapping ก่อน**
เมื่อ DewS ส่ง mapping มา ฉันตีความ sequential (ช่อง 1 = BTN #0, ช่อง 2 = BTN #1...) โดยไม่ถามว่าช่องหมายถึง slot ไหน ถ้าถามชื่อปุ่มตอนแรกจะไม่เกิด re-work 2 รอบ rule: เมื่อ user ส่ง numbered list ให้ match กับ visible label ไม่ใช่ array index

**3. ตอบช้าเรื่อง data quality**
DewS ถามว่า features มีจริงไหม ฉัน delegate ไป Explore agent แล้วรอ — ใช้เวลาพอสมควร ถ้ารู้จัก codebase ดีพอ น่าจะ grep เองได้เร็วกว่า

## Lessons Learned

1. **Static เหนือกว่า dynamic เสมอถ้า use case รองรับได้** — รูป workshop ไม่ได้เปลี่ยนบ่อย ใช้ `<img src>` ตรงๆ ดีกว่าระบบ upload + localStorage ทุกวิธี
2. **ถาม label ก่อน assign** — เมื่อ user ส่ง numbered list ให้ map กับ visible button label ไม่ใช่ DOM index
3. **Verify before switching tech** — อย่าเปลี่ยน storage layer โดยไม่รู้ root cause จริงๆ
