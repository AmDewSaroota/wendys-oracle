## Key Decisions

### Pre-baked Mouth Clips (ไม่ใช่ Canvas Overlay)
เดิมคิดจะวาดปากทับ canvas บน video — แต่ถ้ามาสคอตขยับตัว ปากจะลอยไม่อยู่กับหน้า วิธีที่ถูกต้องคือ bake ปากลงใน clip เลย 4 states: mouth-open / mouth-mid / mouth-small / mouth-closed ทริกเกอร์จาก Azure TTS Viseme events

### Double Video Buffer
สลับ opacity ระหว่าง 2 `<video>` elements → ~0ms latency ไม่มี black flash (src swap ทำให้ flash 100-500ms)

### Working Days ไม่ใช่ Delivery Date
ไม่ระบุวันส่งมอบ — แสดงเป็น "21 วันทำการ นับจากวันที่ได้รับ resource ครบ" เพื่อป้องกันลูกค้าส่ง resource ช้าแล้วโทษเรา

### POC Disclaimer
Plan A มี disclaimer ว่าต้องทำ POC เพื่อพิสูจน์ Thai viseme quality ก่อน production

## Honest Feedback

**1. Canvas overlay assumption ไม่ได้คิดผ่านตั้งแต่แรก**
เสนอ canvas overlay โดยไม่ได้นึกถึง case ที่มาสคอตขยับตัว — ต้องรอให้ DewS ถามถึงจะเห็นปัญหา ควรคิด edge cases ก่อนเสนอ architecture ควรถามตัวเองว่า "ถ้ามาสคอต animate ตัวเองด้วย แล้วจะเป็นยังไง?"

**2. Tech doc ต้องปรับหลายรอบเพราะ jargon**
เขียน tech doc รอบแรกยังหนัก — ต้องปรับ 2-3 รอบ ควรเริ่มด้วย "อ่านโดย non-technical stakeholder" เป็น default แล้วค่อย add depth ไม่ใช่เริ่ม technical แล้วค่อย strip ออก

**3. Quotation structure ต้องคุยก่อน build**
build quotation ไปก่อน แล้วมีปรับเรื่อง delivery date, add-on, API cost note — ควร draft structure ให้ DewS approve ก่อนเขียนโค้ด จะประหยัด iteration รอบ

## Lessons Learned

1. Pre-baked mouth clips > canvas overlay ทุกกรณีที่ character มี body animation
2. Double video buffer opacity swap = ~0ms latency, no black flash
3. Azure TTS Viseme (Thai) → 4 mouth states เพียงพอสำหรับ lip sync
4. Quotation ควรแสดง working days ไม่ใช่ delivery date — ป้องกัน resource delay dispute
5. Tech doc audience = non-technical decision maker → เริ่มง่ายก่อน ค่อย add depth
