## Honest Feedback

**1. Slide count verification ล้มเหลวสองครั้ง**
ทั้ง Gemini และตัวฉันเองบอกตัวเลขผิดในช่วงต้น — Gemini บอก 40, ฉันบอก 37, จริงคือ 41 (ตอนนั้น ก่อน delete) ปัญหาคือทั้งคู่ไม่ได้ grep จริงๆ Gemini นับจาก slide-num tag (ซึ่งมี gaps เช่น 16/17 ถูกลบ), ฉันนับจาก comment ใน HTML ซึ่งไม่ reliable สิ่งที่ถูกต้องคือ `Select-String class="slide"` ซึ่งต้องทำตั้งแต่แรก

**2. Tooltip implementation ต้องแก้ 2 รอบ**
รอบแรกใช้ CSS `::after` + `position:absolute` — ไม่ดูก่อนว่า slide มี `overflow:hidden` อยู่ ถ้า verify slide CSS ก่อนจะเห็นทันทีว่าต้องใช้ fixed position รอบที่สองถึงทำถูก แต่ DewS ต้องส่ง screenshot มาให้ดูก่อน

**3. Gemini verification ยังไม่ tight พอในบางจุด**
แม้จะมี feedback memory และ protocol อยู่แล้ว แต่ช่วงต้นเซสชั่นหลัง compaction ยังมีช่วงที่ relay Gemini output โดยไม่ verify ให้ครบ ต้องระวังว่า context compaction มักทำให้ forget learned behaviors ช่วงแรกๆ ของ session

## Lessons Learned

1. **Grep counts ก่อนพูดเสมอ** — อย่า trust pattern ที่ "น่าจะถูก" เช่น slide-num หรือ comment
2. **CSS overflow check ก่อน implement tooltip** — ถ้าจะทำ overlay/popup ใน container ที่อาจมี overflow:hidden ต้องใช้ fixed/portal approach
3. **Human/Oracle split = design filter** — ทุก slide content ต้องผ่านคำถาม "มนุษย์ต้องรู้เพื่อตัดสินใจ หรือ Oracle ทำให้ได้?"
4. **Post-compaction: re-verify behaviors ทันที** — memory อาจไม่ถูก load ครบในช่วงแรก ควรอ่าน feedback memories ทันทีหลัง compaction
