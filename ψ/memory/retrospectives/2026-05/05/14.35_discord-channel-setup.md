## Honest Feedback

1. **CRLF bug was preventable** -- I should have written the .env file with explicit LF line endings on Windows. This is a known cross-platform issue and I created unnecessary friction by not handling it. The other WEnDyS session had to fix my mistake.

2. **Too many back-and-forth on /mcp check** -- When the bot was not responding, I should have immediately suspected the .env CRLF issue instead of sending DewS through multiple /mcp autocomplete screens. I wasted her time with UI navigation that was not productive.

3. **OAuth error not anticipated** -- After a major Claude Code update (v2.1.51 -> v2.1.128), re-authentication is expected. I should have warned DewS before she ran the command, not after the error appeared.

## Lessons Learned

- Windows Write tool creates CRLF files -- for Unix-targeting config files (.env), must ensure LF line endings
- Claude Code update may require re-auth -- warn before running `claude` after `npm install -g`
- Discord bot token can be decoded to get client ID (base64 decode first segment)
- Bot shows online only when Claude Code runs with `--channels` flag -- no flag = offline
