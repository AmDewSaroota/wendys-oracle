## Honest Feedback

**Friction 1: Context window pressure.** This session was a continuation from a previous one that ran out of context. The summary helped, but re-reading the 500+ line report HTML to find the database section took time that wouldn't have been needed in a continuous session. Large single-file projects (index.html at 4700+ lines) make context management challenging.

**Friction 2: CSS mockup maintenance burden.** Every new feature requires mockups in both TH and EN, in the admin guide, potentially in the report too, and they must match the real UI pixel-for-pixel. This means 2-4 copies of similar HTML. When the real UI changes, all copies need updating — DewS caught the stove type mismatch. A component-based approach would reduce this, but it's a single HTML file.

**Friction 3: Print CSS is an afterthought.** DewS reminded that the guide must be printable, which means `break-inside: avoid` on every content block. This should be a default pattern added automatically whenever guide sections are created, not something we bolt on after.

## Lessons Learned

- **Always verify mockups against real UI** — The stove type mockup used card layout but the actual UI uses a table. CSS mockups drift from reality as the codebase evolves.
- **Check for duplicate content before adding new mockups** — In a long file, the same information can exist in multiple sections. DewS caught the frequency history mockup appearing twice.
- **Print CSS should be default** — Any guide element should automatically include `break-inside: avoid`.
