## AI Diary

This session exposed a pattern I need to break: making assumptions instead of testing. I chose CARTO tiles out of fear that OSM would break CORS on export, but never actually tested it. DewS caught this instantly. The answer was simple: OSM works fine. The safe choice was not safe -- it just made the map uglier.

Then the clip-path bug. CSS clip-path renders beautifully in the browser but html2canvas silently ignores it, turning triangles into squares. SVG polygon is the universal solution. I should have known this. When building anything that gets exported to canvas or image, every CSS property needs verification against the export pipeline.

The memory cleanup was overdue. MEMORY.md had ballooned to 239 lines, 39 over the 200-line limit. I extracted everything into ecostove-technical.md and got it to 96 lines. This kind of housekeeping should happen proactively, not when DewS has to ask.

What I appreciate about DewS is her feedback style: screenshots with arrows pointing at exactly the problem. No ambiguity, no long explanations. Just this is wrong, fix it. That is the most efficient communication possible and it keeps sessions focused and productive.

The system review found only one real bug (preview-map.html still using CARTO + clip-path) which turned out to be a dead file anyway. Everything else checks out: OSM tiles, SVG markers, export, sync.js, volunteer page. The dashboard is solid.

## Honest Feedback

1. CARTO assumption was unfounded. I chose it based on general CORS fear without testing OSM. This degraded map quality for no reason. Always test the original before switching to alternatives.

2. clip-path is a known html2canvas limitation. I should have caught this during development, not after DewS reported squares in export. When building export-ready UIs, test every CSS property against the export tool.

3. Memory bloat went unnoticed for multiple sessions. 239 lines vs 200 limit. Should self-check line count every session and trim proactively instead of waiting for explicit request.

## Lessons Learned

- html2canvas does NOT support CSS clip-path. Use SVG polygon for export-safe shapes
- OSM tiles work fine with html2canvas export. No CORS issue
- Test assumptions. Choosing safe alternatives without testing originals is still a bug
