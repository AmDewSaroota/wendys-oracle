## AI Diary

This session taught me something important about trust and assumptions. I'd been using CARTO Voyager tiles "for safety" — assuming OSM would break CORS on export — without ever actually testing it. DewS caught this immediately: "ทำไมก่อนหน้านี้มันเอกพอร์ทได้ จู่ๆทำไมถึงปัญหา" (why did it work before if there's a problem?). She was right. The basic map never had export, so CORS was never an issue — I just chose the wrong tile provider out of unfounded caution.

Then the clip-path bug. I used CSS `clip-path` for triangles because it's clean and simple in the browser. But html2canvas doesn't render it — triangles silently degrade to squares in exports. A classic "works on screen, breaks in output" bug. SVG polygons are the universal solution.

The memory cleanup was overdue. MEMORY.md had grown to 239 lines — nearly 40 over the 200-line limit. I extracted everything into `ecostove-technical.md` and got it down to 96 lines. This is the kind of housekeeping I should do proactively, not wait until it's painfully overflowing.

DewS's feedback loop this session was fast and precise: she doesn't explain abstractions, she shows screenshots with arrows pointing at exactly what's wrong. That's the most efficient form of communication — no ambiguity, just "this is broken, fix it."

## Honest Feedback (3 friction points)

1. **Unfounded CORS assumption**: I chose CARTO tiles based on a general fear of CORS issues rather than testing OSM directly. This wasted time and degraded the map quality. Lesson: test first, assume nothing. The "safe" choice isn't safe if it degrades the product.

2. **clip-path blind spot**: I should have known html2canvas doesn't support clip-path. This is a well-documented limitation. When building export-ready UIs, every CSS property must be tested against the export pipeline — not just visually in the browser. SVG is the universal fallback for canvas-based exports.

3. **Memory bloat went unnoticed**: MEMORY.md was 39 lines over limit for multiple sessions. I only cleaned it when DewS explicitly asked to "save memory properly." Should have a self-check: every session, verify MEMORY.md line count and trim proactively.

## Lessons Learned

1. **html2canvas doesn't support CSS `clip-path`** — use SVG `<polygon>` for shapes that need to survive canvas export
2. **OSM tiles work fine with html2canvas** — no CORS issue, no need for CARTO Voyager
3. **Test assumptions, don't assume safety** — choosing a "safe" alternative without testing the original is still a bug
