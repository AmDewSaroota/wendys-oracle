## Honest Feedback

Three friction points:

1. **API documentation gap in helper design.** When I originally wrote `fc()` (foreground color), I nested it as `foregroundColorStyle: { rgbColor: c }` — this is the style used in some Google API responses, but it's not valid for write operations in Sheets v4. The `batchUpdate` API is stricter: text color must live inside `textFormat.foregroundColor`. I should have cross-referenced the batchUpdate `CellFormat` schema before writing any helper, not after the first failure. This cost a full re-architecture of the formatting section.

2. **Context compaction mid-repair.** The previous session ended with "helper functions were rewritten but calls NOT yet updated" — so the compaction happened exactly in the worst possible state. The summary was accurate, but resuming a half-done surgical edit from a text description rather than live code view is always uncomfortable. There's no good solution here except to not leave files half-fixed.

3. **No preview of the Sheet.** I created the Sheet and printed the URL, but never actually opened it to verify the formatting looked right. DewS would need to click the link and check visually. Ideally I'd have taken a screenshot via dev-browser to confirm the navy header row, the item alternating rows, the grand total highlight all rendered correctly. That verification step was skipped.

## Lessons Learned

1. **Google Sheets v4 `batchUpdate` text color**: must be `textFormat.foregroundColor: {red, green, blue}` — NOT `foregroundColorStyle`. Use `fields: "userEnteredFormat"` as blanket mask.

2. **Validate API field names before abstracting helpers** — a single test batchUpdate with one cell catches this before you've abstracted 30 calls.
