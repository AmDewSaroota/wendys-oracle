## Honest Feedback

**Friction 1**: The ICO creation loop took 4+ attempts and required consulting Gemini. I should have known the PNG-in-ICO binary format from the start — it's documented in the ICO spec. Instead I tried quick hacks (GetHicon, naive PNG wrap) that predictably failed. The `[byte[]]` cast issue in PS 5.1 is a known gotcha for anyone who's worked with PowerShell + generics. Gemini caught it; I should have.

**Friction 2**: The summary tab expand/collapse adds a `summaryExpanded` object that tracks open/closed state. But when `renderSummary` re-renders (e.g., switching filter), it preserves the state correctly because it reads from the module-level variable before writing innerHTML. However this means the state persists even when switching back to timeline and back — which is fine but wasn't explicitly tested. Edge cases around stale state in summary view could surface.

**Friction 3**: The PDF export generates a `blob:` URL and opens it via a programmatic `a.click()`. This works in Chrome but may not work in all browsers. More importantly, the exported HTML references Google Fonts via CDN (`fonts.googleapis.com`) — if DewS opens the PDF export offline, the Sarabun font won't load. The app itself works fully offline (single HTML file), but the export has an online dependency that I didn't flag.

## Lessons Learned

- **PNG-in-ICO requires explicit header**: 6-byte ICONDIR + 16-byte ICONDIRENTRY per image. Missing the directory = "contains no icons" error. Width byte = 0 means 256 (ICO spec).
- **PowerShell 5.1 + List[byte].AddRange**: Must cast to `[byte[]]` explicitly — `@(1,0)` is `Object[]` and AddRange rejects it silently or throws.
- **Hotel multi-night needs date arithmetic**: `contBlocks` can't just check `prevDate` — needs to check if `b.date + b.nights >= currentDate`.
- **Height zones beat equal rows for timeline bars**: When blocks have natural "importance" hierarchy (full-day spans vs point events), use height to encode that — not separate rows.
