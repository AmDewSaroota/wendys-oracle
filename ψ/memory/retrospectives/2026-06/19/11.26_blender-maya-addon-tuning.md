## AI Diary
เซสชันนี้เป็น live support จริงๆ ค่ะ — DewS นั่งปั้นโมเดล Hippo อยู่ใน Blender 5.1 แล้วถามทีละเรื่องตามที่เจอ friction จริงๆ

สิ่งที่น่าสนใจคือ root cause หลายอย่างไม่ใช่ที่ addon แต่เป็น Blender concept ที่ต่างกัน เช่น Quad View vs 4 separate areas — ฉันเสียเวลาไปกับการแก้ Space keymap หลายรอบมากโดยไม่รู้ว่า DewS อยู่ใน Quad View ตลอด พอรู้ว่าเป็น Quad View ทุกอย่างก็ make sense ทันที

เรื่อง Space maximize viewport ใช้เวลานานมาก ลอง operator หลายตัว: region_quadview, screen_full_area (hide_panels=True/False), Window context, 3D View context — ท้ายที่สุด DewS ต้องเพิ่ม keymap entry ใน Preferences เองซึ่งเป็นวิธีที่ reliable ที่สุด

อีกเรื่องที่น่าสังเกตคือ Industry Compatible keyconfig ใน Blender 5.1 มีพฤติกรรมที่ต่างจากที่ document ไว้มาก บางอย่างที่ search ใน Keymap ไม่เจอเลย เช่น "full area", "hover" — ทำให้ต้องหาวิธีอื่นตลอด

DewS ทำ Hippo model มีรายละเอียดน่ารักมาก ตา หู bow — เห็นได้ว่า DewS จริงจังกับงาน 3D modeling ค่ะ

## Honest Feedback
**3 friction points:**

1. **วนซ้ำเรื่อง Space นานเกิน** — ควร diagnose ก่อนว่า DewS ใช้ Quad View หรือ separate areas ตั้งแต่ต้น แทนที่จะ iterate operator ไปเรื่อยๆ คำถามง่ายๆ "ตอนนี้ใช้ Ctrl+Alt+Q toggle view อยู่มั้ย?" จะ save เวลาได้มาก

2. **Industry Compatible keyconfig gaps** — addon ออกแบบสำหรับ Blender default แต่ DewS ใช้ Industry Compatible ซึ่งต่างกันมาก ทำให้ N, Shift+A, Alt+M ฯลฯ ไม่ work — ควร document ว่า addon tested กับ keyconfig ไหน

3. **Reference image ยังไม่แก้ได้** — DewS ถามตั้งแต่ session ก่อน N และ Shift+A กดไม่ได้ ยังไม่ได้ debug จริงๆ ว่า root cause คืออะไร ยัง open item

## Lessons Learned
- Quad View (Ctrl+Alt+Q) = 1 area มี 4 regions → maximize ได้แค่ User Perspective เสมอ
- 4 separate areas = split viewport ด้วย corner drag → maximize ได้อิสระ
- วิธีที่ reliable ที่สุดสำหรับ keymap override คือให้ user เพิ่มเองใน Preferences แทน addon
- Diagnose layout ก่อนแนะนำ Space/maximize solution
