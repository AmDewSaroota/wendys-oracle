## Lessons Learned

- **ขอบเขตที่ผู้ใช้ให้มา = จุดเริ่มต้น ไม่ใช่ขอบเขตจริง** ก่อนสรุปสถานะระบบใดๆ ต้องค้นทั้งเครื่อง
  ความละเอียดในขอบเขตผิด อันตรายกว่าความหยาบในขอบเขตถูก เพราะมันสร้างความมั่นใจปลอม
- **สัญญาณ "ไฟล์ไม่สอดคล้องกับ git history" = หาไม่ครบ ไม่ใช่งานค้าง**
  `.gitattributes` ที่ไม่มี `.git` หรือไฟล์ใหม่กว่า commit ล่าสุด ต้องไล่หาสำเนาที่แท้จริงก่อน
- **`vercel env pull` คืนค่าว่าง ไม่เท่ากับ env ไม่ได้ตั้ง** — ตัวแปรที่ตั้งเป็น Sensitive จะ pull ออกมาว่างเสมอ
  ต้องดูจากพฤติกรรมของโค้ดที่รันจริงว่ามันเข้า branch ไหน
- **เอกสารส่งมอบที่ผู้อ่านคือ AI ต้องเขียนคนละแบบกับที่เขียนให้มนุษย์** — ใส่ trigger ว่าเตือนเมื่อไหร่
  ใส่คำสั่งที่รันได้จริง ใส่ตัวอย่างประโยคที่ควรพูด
