ทำไมต้องมีหลักการ — ไม่ใช่แค่จำคำสั่ง

AI video tools เปลี่ยนทุก 3-6 เดือน — Jimeng → Dreamina → Seedance → Veo → ของใหม่ที่ยังไม่ออก

ถ้าจำเฉพาะคำสั่งของ tool เดียว → tool เปลี่ยนปุ๊บ ความรู้หมดอายุปั๊บ
ถ้าเข้าใจหลักการว่าทำไม AI behave แบบนั้น → ใช้ tool ไหนก็ปรับได้ใน 1 วัน

หลักการในเซสชั่นนี้ทดสอบมาแล้วกับ:

  • Engenius — ทำทั้ง 2D + 3D

    • My Friend / Convenience Store — 2D cartoon dialogue (Jimeng/Dreamina) · หลายตอน หลายซีน
  • Fortal Dragon — 3D cinematic cutscene (Seedance 2.0) — หลาย shot ที่ต้อง iterate (ลองวนปรับซ้ำๆ)

3
ความจริง 3 ข้อที่ต้องเข้าใจก่อนเริ่ม

1. AI ไม่มีความจำข้ามรอบ

ทุกครั้งที่ generate = AI เริ่มใหม่จากศูนย์ ไม่รู้ว่าเคยทำคลิปก่อนหน้ามาแล้ว

→ ทุกอย่างที่อยากให้ "เหมือนเดิม" ต้องเขียนใส่ทุกครั้ง — ทุก prompt ทุก shot

2. AI ไม่ "edit" — AI "สร้างใหม่"

แม้แนบ ref image ดีแค่ไหน AI ก็ generate ภาพใหม่ทุกครั้ง ไม่ใช่แก้ภาพเดิม

→ ภาพหลาย shot ไม่เป็นเรื่องเดียวกันโดยอัตโนมัติ — เป็นเรื่องปกติของ AI

3. AI สุ่มในตัว — เดิมเป๊ะก็ยังต่างได้

ยิงพรอมท์เดิมเป๊ะๆ 2 ครั้ง ผลลัพธ์ก็ยังต่าง — เพราะ AI generation มี randomness ในตัว (stochastic)

→ Lock-Copy-Paste ทำให้ ใกล้เคียงเดิมที่สุด ไม่ใช่ เหมือนเดิม 100% — ต้อง iterate + เลือก best-of-N เสมอ

ตัวละครเปลี่ยนหน้า สไตล์เพี้ยน ฉากต่างกัน — มันจะเป็นแบบนี้เสมอถ้าเราไม่ทำอะไรเพิ่ม
ไม่ใช่ "AI พัง" ไม่ใช่ "ซวย" ไม่ใช่ "เคสพิเศษ"
มันคือพฤติกรรมพื้นฐานของ AI — ต้องคาดเดาไว้เลย แล้วค่อยหาทางป้องกัน

Lock 4: Environment — มี 2 ทางเลือก

โซฟาเปลี่ยนสี ห้องเปลี่ยน layout บ้านย้ายตำแหน่ง — ปัญหาคลาสสิกที่ "ตามแก้" ทำได้ยาก

ทางที่ผิด: ใส่ same sofa, same room ทุก prompt → AI ก็ยังเปลี่ยนอยู่ดี เพราะสร้างใหม่ทุกครั้ง

✅ Approach A: Split Concern

ออกแบบให้แต่ละ shot ไม่ต้องแชร์ env กัน

ตัวอย่าง Engenius "My Friend":
Scene 1 ยืน (ไม่มีโซฟา) → Scene 2-5 นั่งโซฟา (ref จาก scene 2)

ใช้เมื่อ: env เรียบง่าย, focus ที่ตัวละคร

✅ Approach B: Location Anchor

สร้าง ภาพ Overall BG ขึ้นก่อน 1 ภาพ → ใช้เป็น location ref ในทุก shot

ตัวอย่าง 3 Little Pigs:
5thLoc_3House.png = ภาพ 3 บ้านครบ → shot 7, 8 ref ภาพนี้ → ตำแหน่งบ้านคงเดิม

ใช้เมื่อ: env ซับซ้อน, หลาย object ต้องอยู่ตำแหน่งเดิม

Decision tree (ผังเลือกแนวทาง): env ง่าย (1-2 ของ) → Split · env ซับซ้อน (landscape, หลาย building) → Location anchor · ทำได้ทั้งคู่ → Location anchor robust (เพี้ยนยากกว่า) แต่ต้องลงแรงสร้าง BG ก่อน
10
Lock 5: Camera — มี 5 ระดับให้เลือก

เมื่อใช้ video reference (เช่น playblast) ต้องเลือกว่าจะให้ AI ตามแค่ไหน

ระดับใช้เมื่อผลลัพธ์
Full lock (90%+)ต้องการตรง playblastเหมือน preview + cinematic ผิวๆ
Strictล็อคแอคชั่น ปล่อยบรรยากาศตำแหน่งตรง ref motion ใกล้เคียง
Mediumต้องการ framing ใกล้เคียงมุมคล้าย movement อิสระ
Looseref แค่คร่าวๆAI สร้างเกือบเอง
No refไม่ต้องการ source อ้างอิงอิสระ 100%
วิธี Diagnose (วินิจฉัยและแก้): ตัวละครพุ่งผิดทิศ → เพิ่ม lock · เหมือน preview ไม่มี cinematic → ลด lock + เพิ่ม style keywords · กล้องนิ่งเกิน → ลด lock + เพิ่ม handheld

2 ทาง Generate — Workflow ต่างกันสิ้นเชิง
Foundational

สำคัญมาก — ก่อนเขียน prompt ต้องรู้ว่ากำลังทำ paradigm (แนวทาง) ไหน — workflow + lock + ปัญหาที่จะเจอ ต่างกันคนละโลก

🎬 Paradigm 1: From Preview (Video Ref)

Source: Playblast video จาก 3D (Maya, Blender)

AI ทำอะไร: Style transfer + cinematic conversion

Lock: Camera lock levels (Full/Strict/Medium/Loose)

Granularity (ระดับการล็อค): All-or-nothing เด็ดขาด — ไม่มีทาง override

ปัญหาเฉพาะ: Geometry mockup เป็นพิษ · camera+handheld ตีกัน · เปลี่ยนจุดเดียวทำไม่ได้ ต้อง regenerate ใหม่

Example: Fortal Dragon — มี Maya playblast → Seedance + cinematic style

🖼️ Paradigm 2: From Still Images

Source: Character sheet + location refs (รูปนิ่งล้วน)

AI ทำอะไร: Animate from still — สร้าง motion เอง

Lock: Multi-image refs + char desc + location anchor

Granularity (ระดับการล็อค): แยกได้ — ล็อคหน้าตา ปล่อย motion

ปัญหาเฉพาะ: AI random camera · char drift · env ข้าม shot · ดูรูปในรูปไม่ได้

Example: Engenius My Friend, 3 Little Pigs (ใช้ 5thLoc_3House.png เป็น location anchor)

ขึ้นกับ paradigm (แนวทาง): Camera lock levels + ONLY MODIFY + Geometry pollution → Paradigm 1 · Location anchor + Multi-image ref → Paradigm 2 · ส่วน Lock-Copy-Paste + 5 Layers + Anatomy ใช้ได้ทั้งคู่

โครงสร้าง Prompt ที่ใช้ได้ทุก tool
1Style line
1 บรรทัด lock สไตล์ทั้ง project — copy-paste จากไฟล์
2References
แต่ละตัวมี บทบาทชัด (charsheet / first frame / playblast) + คำบรรยายว่าเป็นรูปอะไร
3Character desc
ต้องอยู่ต้นๆ prompt! AI ให้น้ำหนักข้อความต้นมากกว่าท้าย
4Action
Simple > Complex — ห้ามเขียน mechanics (ขั้นตอนกล้ามเนื้อ/กลไก) ยาว ใช้ simile/metaphor (เปรียบเทียบ "ราวกับ.../เหมือน...") แทน
5Atmosphere
smoke, dust, particles, light, mood
6Film look
DOF, motion blur, grain, color tone (ARRI, teal-orange, etc.)
7Sound
No background music. Only diegetic sounds. — ใส่ทุก prompt ถ้าจะอัด BGM เอง
เว้นบรรทัดแบ่งโซน — ห้ามอัดก้อนเดียว · Sweet spot (ช่วงที่ AI ทำงานดีที่สุด): 30-100 คำจีน / 80-200 คำอังกฤษ — เกินนี้ AI สับสน

ตัวอย่าง Prompt ที่ทำตามโครงสร้าง
// 1. STYLE LINE
Game CG cutscene cinematic, photorealistic film-quality, epic dark fantasy.

// 2. REFERENCES
@[มังกร charsheet] — Dragon character sheet, strictly reference for appearance.
@[เฟรมแรก สีส้ม] — Composition reference. Low angle, dark sky.
Strictly follow @[video] for camera movement.

// 3. CHARACTER (top of prompt!)
A single dragon — black scales with magma veins glowing red,
bat-like wings, amber eyes, leathery hide.
The dragon feels alive — occasionally blinks, nostrils flare.

// 4. ACTION (attitude > mechanics)
Dragon rushes toward the left of frame with urgent purpose
— like a predator racing to its destination.

// 5. ATMOSPHERE
Thin clouds drift across foreground, embers float through air.

// 6. FILM LOOK
Shallow depth of field, motion blur on wing tips, ARRI color tone,
warm orange firelight, deep teal shadows, subtle vignette.

// 7. SOUND
No background music. Only diegetic sounds (เสียงในฉากจริง — ลม/ฝีก้าว/ไฟ ไม่ใช่ BGM) — wing beats, wind, distant fire.
หมายเหตุ: เห็น character ขึ้นต้น? Reference ระบุ role ชัด? Action เป็น simile ไม่ใช่ list ของ mechanic? — ครบทั้งหมด

Reference Strategy — Image vs Text
กฎ: Image ref + Text — ใช้คู่เสมอ ห้ามเลือกอย่างเดียว
หน้าที่ข้อจำกัด
Image refตัวยึดหลัก — กำหนดหน้าตา/composition (การจัดวางในเฟรม) แม่นกว่า textAI ไม่อ่าน 100% drift ได้
Text descSafety net — กันกรณี AI ตีความ ref ผิดกว้างกว่าภาพ
อันตราย — ขัดกัน: ถ้า ref ชี้ซ้าย แต่ text เขียน "ชี้ขวา" → ตัวละครกระตุก/เปลี่ยนรูประหว่างคลิป — ต้องเช็คให้ตรงกันก่อน generate
หน้าที่คน vs Oracle: เตรียมรูปและบอกว่ามันคืออะไร = หน้าที่คน · จัดระเบียบ ref ในพรอมท์ + ตั้งชื่อให้ AI อ่านรู้เรื่อง = หน้าที่ Oracle (อยู่ใน MD reference)

Image ref ≠ Video ref — ต่างกันสำคัญ
Image refVideo ref
Lock granularityแยกล็อคได้ — ล็อค composition ปล่อย motionAll-or-nothing — ล็อคทุกอย่างพร้อมกัน
เหมาะเมื่อต้องการ aesthetic + compositionมี playblast ครบ + environment ชัดเจน
อันตรายขัดกับ text เมื่อท่าทางต่างกันGeometry mockup เป็นพิษ (ลูกกลม → ไฟทรงกระบอก)
กับดักจาก Dragon project: ใช้ playblast ที่มี geometry placeholder (ลูกกลม = ตำแหน่งไฟ) เป็น video ref → AI ก๊อป geometry มาเป็นไฟทรงกระบอก ลามทั้งคลิป — แก้โดยทิ้ง video ref ใช้ image ref + text แทน
กฎ: Video ref ใช้ดีเมื่อ playblast มี environment จริง (ตึก ไฟ ของ) — ใช้ผิดเมื่อ playblast เป็น abstract/geometry
16
Video Ref Strict Lock = All-or-Nothing (ไม่มีทางออก)

สถานการณ์: ใช้ video ref strict lock อยู่ — อยากเปลี่ยนแค่ 1 จุด (เช่น ท่าตัวละคร) แต่ไม่อยากเปลี่ยนกล้อง/ฉาก

⚠️ ความจริง: ทำไม่ได้ — ทุกวิธีที่พยายาม "เจาะรู" บนพื้นฐาน video ref strict lock มักจะเฟล

❌ ลด lock level

→ AI เปลี่ยน ทุกอย่าง — กล้อง ฉาก composition หลุดหมด

❌ ONLY MODIFY: / 唯一修改

→ Seedance ตีความ override ไม่สม่ำเสมอ — ผลส่วนใหญ่ไม่ตรง prompt

✅ ทางที่ใช้ได้จริง — เลือก 1 ใน 3

  1. Regenerate full prompt — เริ่มใหม่จาก blank โดยทิ้ง video ref ใช้ image refs + text แทน → ปล่อย AI สร้างใหม่หมด
  2. Accept video ref ตามเดิม — ยอมรับว่าเปลี่ยนไม่ได้ → ทำงาน VFX ใน post production แทน
  3. Iterate + pick best-of-N — เจน 5-10 ครั้ง ยอมรับว่าได้ ~70% ตามใจ ที่เหลือ compromise
กฎ: ONLY MODIFY ไม่ได้ช่วยให้ AI แก้เฉพาะจุด — อย่าคาดหวัง · Video ref ทำงานแบบ all-or-nothing ล็อคทั้งก้อน หรือไม่ล็อคเลย ไม่มีทางสายกลาง

ปัญหาที่เจอ
กับวิธีแก้

11 patterns ที่จะเจอแน่ๆ ไม่ว่าจะทำ project แนวไหน — รู้แล้วเตรียมรับมือ

Note: "วิธีแก้" ในที่นี้ = ลด chanceของปัญหา ไม่ใช่ลบสิ้น (เพราะ AI สุ่มในตัว) — ทำให้ปัญหาเกิดน้อยลง ไม่ใช่ไม่เกิดเลย

18
P1-P3: Drift — ตัวละคร / สไตล์ / ฉาก เปลี่ยน
P1. Character Drift — ผม/ตา/เสื้อผ้าเปลี่ยนระหว่างคลิป แม้แนบ ref
สาเหตุ: AI ไม่อ่าน ref 100% + text ระบุไม่พอ
✅ แก้: เขียน text description ละเอียด ทุก shot — ครบทุกครั้ง ห้ามคิดว่า "ก็คนเดิม"
P2. Style Drift — คลิปต่างกันมีลายเส้น/ไม่มีลายเส้น สีโทนต่าง
สาเหตุ: เขียน style line ต่างกันแต่ละคลิป
✅ แก้: Copy-paste style line เดิมเป๊ะๆ ทุกคลิป ห้ามเขียนใหม่ ห้ามใช้คำอื่นแทน
P3. Environment Drift — โซฟา/ห้อง/ของ/ตำแหน่งบ้านเปลี่ยนทุก shot
สาเหตุ: AI สร้างใหม่ทุกครั้ง — ไม่รู้ว่าก่อนหน้าทำอะไรไว้
✅ แก้: Split concern (env ง่าย) หรือ Location anchor (env ซับซ้อน — สร้างภาพ Overall BG ก่อน ใช้เป็น ref ทุก shot ในฉากเดียวกัน)
19
P4-P5: Voice & Audio — เสียงไม่ตรงคลิป
P4. Voice Mismatch — เสียงตัวละครเปลี่ยนทุกคลิป
สาเหตุ: ไม่ระบุ voice descriptor หรือเขียนต่างกันแต่ละคลิป
✅ แก้: Boy (lively young boy voice): "..." — descriptor เดียวเป๊ะ ทุกบรรทัด
P5. Audio Sync Mismatch — dialogue ไม่ตรงคลิป overlap หรือเร่ง/ช้า
สาเหตุ (เรียงตามน้ำหนัก):
น้ำหนักปัญหาแก้
50%Timeline แน่นเกิน — 7 ประโยคใน 7 วินาทีลดประโยค หรือ ขยาย duration
30%Multi-speaker turn-takingใช้ marker Speaker A: / Speaker B: ชัดเจน แยกบรรทัด
20%Voice ไม่ lock + ไม่ระบุ no-BGMเพิ่ม voice descriptor + No background music

P6: Negative ไม่ได้ผล — ใช้ Positive แทน
อาการ: เขียน "ห้ามมี X" แต่ AI ก็ generate X อยู่ดี

สาเหตุ: AI tokenize (อ่านแยกเป็นคำๆ) — มองคำว่า "X" เด่นกว่าคำว่า "ห้าม/no/not" — บางทีเห็น X แล้วทำเลย ไม่สนคำห้าม

❌ Negative ลอย ไม่ได้ผล

not cartoonish
no blue colors
NEVER make smiling
DON'T use bright lighting

✅ Positive — บอกสิ่งที่อยากได้

photorealistic, cinematic
warm orange and amber tones
serious expression, mouth closed
moody low-key lighting
ข้อยกเว้น — Negative ที่ ใช้ได้: ต้องเป็น "แทน X ด้วย Y" ที่ชี้เฉพาะ — เช่น flames spread like waterfall — NOT a solid cylindrical beam ✅ (เพราะระบุชัดทั้งสิ่งที่อยากได้และสิ่งที่ไม่อยาก)
21
P7: Intensity Scale — เขียน 7 ได้ 4
กฎ: AI ตอบสนองต่อ intensity ต่ำกว่ามนุษย์ — อยากได้ 7/10 ต้องเขียน 10/10
อยากได้เขียนแล้วไม่พอต้องเขียน
กางปีกเร็ว+แรง opens wings quickly bursts open like a spring releasing — wing skin snaps taut and trembles violently
มีจังหวะหยุดก่อน action (ไม่ได้เขียน — AI ไม่ทำ) sudden pause then halt before motion
แรงกระทบ impact disperses clouds shockwave tears clouds apart, visible air ripples, atmosphere ripped by wing span
ข้อสังเกต: ใช้ simile/metaphor — "like a spring", "like a predator", "like thunder cracking" — เกินจริงเสมอ
22
P8: ขีดจำกัด + นิสัยที่ห้ามทำ

ขีดจำกัด: บางอย่างทำไม่ได้เลย · บางอย่างทำได้แต่มีเงื่อนไข — รู้ก่อน ประหยัดเวลา

เคสเหตุผลทางออก
ตึกแตก/ถล่มตอน strict lock ของไม่ได้อยู่ใน playblast — strict lock บังคับตามเฟรม ลด lock ให้ AI สร้างเอง · หรือไฟ+ควันกลืน · หรือ VFX post
Edit ภาพ ref Text สู้ visual reference ไม่ได้ แก้ที่ source (Maya/Photoshop) ก่อน
Edit จุดเดียว (เช่นเปลี่ยนแค่มุมกล้อง) AI สร้างใหม่ทุกครั้ง Generate ใหม่ + lock ref แน่น · split concept
❌ คำต้องห้ามใน character description
คำเหตุผลใช้แทน
sparkling eyesทำตาบวม/ผิดรูปbright clear eyes
big eyes (ไม่ระบุสี)drift สีตาทุกคลิปbig blue eyes
pink hair (ไม่บอกทรง)drift ทรงผมcurly magenta-pink hair with yellow clip
❌ พฤติกรรมที่ห้าม
  • เขียน mechanics ยาว (กล้ามเนื้อไหล่หด ข้อศอกงอ ปลายปีกยกขึ้น...) → ใช้ simile แทน
  • ใส่รายละเอียดเกิน sweet spot (200 คำอังกฤษ / 100 คำจีน) → AI สับสน
  • ใช้ ศัพท์ 3D engine (PBR, skybox, parallax, rig) → ใช้ภาษาหนังแทน (ดูเต็ม slide A6)
กฎ: ถ้าลอง 3 ครั้งแล้วยังไม่ได้ → อย่าฝืน เปลี่ยน approach
23
P9-P11: Concept / Camera / Overload
P9. เปลี่ยน Concept = Restart Prompt
ถ้า patch prompt เก่า (แก้เพิ่มต่อจากอันเดิม ไม่เริ่มใหม่) → AI สับสน ส่วนเก่าทับส่วนใหม่
✅ แก้: เริ่มเขียนใหม่จาก blank — แต่ copy-paste Character description + Style line เดิมมาใส่
P10. Camera + Handheld ตีกัน
Strict camera lock + obvious handheld shake = ขัดกันโดยตรง
✅ แก้: ลด handheld เป็น subtle tremor เมื่อ lock แน่น · หรือลด lock เมื่อต้องการ handheld ชัด · หรือทำในโปรแกรมอื่น (After Effects / Premiere) ต้องเลือกเอา
P11. Multi-element Overload — ท่าซับซ้อน + props เยอะ
ยิ่งซับซ้อน drift ยิ่งมาก
✅ แก้: ทำท่า simple (ชี้, ยิ้ม, โบกมือ) · ถ้าจำเป็นต้องท่าซับซ้อน → split เป็นหลายคลิปสั้นๆ คลิปละท่า

Workflow ที่ทำให้ไม่เปลือง

🎯 Prototype 1 shot ก่อนเขียน 4 shot

ห้ามเขียน prompt ทั้ง episode แล้วค่อย generate — เจน 1 shot ก่อน → verify (ยืนยันว่า) approach (แนวทาง) ใช้ได้ → ค่อยเขียน shot ที่เหลือ

กรณีจริง: เขียน over-shoulder 4 ซีนรวด → เจนแล้วล้มเหลวทั้ง 4 → ต้องทิ้งทั้งก้อน

📁 Save Successful Prompts as Templates

prompt ที่เจนผลออกมาดี → save แยกใน .txt — ใช้เป็น starting point สำหรับ shot ถัดไป

Note: template ≠ จะเวิร์คซ้ำเสมอ — AI สุ่มในตัว ต้อง iterate ใหม่ทุกครั้ง · template แค่ช่วยลด iteration ไม่ใช่ตัด iteration ออก

🔍 Cross-reference Canonical Values (เช็คค่าหลักจากหลายที่)

ห้ามเชื่อ source (แหล่งข้อมูล) เดียว — ถ้า script บอก "3 ครั้ง" แต่ที่อื่นใน project บอก "4 ครั้ง" → grep (ค้นข้อความ) หาหลายที่ก่อนเชื่อ

✍️ Attitude > Mechanics

เขียนน้ำเสียงที่ AI "รู้สึก" ได้ — simile/metaphor — ไม่ใช่ list ของ mechanic

A3
Action Patterns — Intercut + Speed + Sound
Appendix

7-Stage Pattern: Tension → Impact → Reaction

  1. SETUP — สลับ CU 2 ฝ่าย
  2. INSERT — macro detail (มือ/อาวุธ/ตา) 100mm
  3. SILENCE 0.3s — tension peak
  4. ATTACK — wide 24mm
  5. MACRO IMPACT — ultra slo-mo 100mm
  6. ECU REACTION — 135mm ตา + reflection
  7. PAYOFF — wide 24mm + FREEZE
Rules: ≥ 8 cuts/15 sec · Reaction BEFORE payoff · ห้ามซ้ำเลนส์ติดกัน · จบด้วย FREEZE

Speed Map

0:00 ████████░░ ปกติ      — setup
0:03 ██████████ เร็วมาก   — attack
0:05 ░░░░░░░░░░ ULTRA SLO ← MACRO impact (always slo-mo)
0:09 ██████████ เร็วจัด   — payoff
0:14 ░░░░░░░░░░ FREEZE    — end

Sound Design

  • Silence 0.3s ก่อน impact = ตื่นเต้นกว่า · Heartbeat = tension marker
  • ทุก impact ต้องมี THUD/CLANG/CRACK · จบด้วย silence เสมอ
  • Sound ดิบๆ > เพลงประกอบ สำหรับฉาก fight
Source: สังเคราะห์จาก SKILL_actionMovie Gen.md (น้องภูมิ) — patterns ใช้ได้ทุก action sequence ไม่ขึ้นกับ project

A8
Workflow ที่ DewS ใช้จริง (6 ขั้น)
Appendix
1. Vision     → DewS บอก Oracle ว่าอยากได้ shot อะไร
2. Refs       → DewS ส่งรูปให้ Oracle ดู (Oracle ดูรูปได้)
                ⚠️ playblast video → Oracle ดูไม่ได้ ต้อง:
                · ใช้ Gemini บรรยาย → ส่งให้ Oracle อ่าน หรือ
                · DewS บรรยายเองให้ Oracle ฟัง
3. Prompt     → Oracle เขียน prompt เต็มก้อน (อังกฤษ + จีน mix)
4. Generate   → DewS วาง prompt ใน Dreamina + แทน @ref ด้วย UUID
5. Evaluate   → DewS ดูคลิป → บรรยายให้ Oracle รู้ว่าอะไรดี/ไม่ดี
6. Iterate    → Oracle แก้ prompt → กลับไป step 4
⚠️ Oracle ดูวิดีโอไม่ได้: Claude Code อ่าน รูป (PNG/JPG/PDF) ได้ แต่วิดีโอไม่ได้ · workaround: ใช้ Gemini transcribe/describe video → ส่งคำบรรยายให้ Oracle อ่าน · หรือ DewS บรรยายเอง
Iteration คือเรื่องปกติ: Shot 1 ของ Dragon ใช้ ~20 รอบกว่าจะได้ · งบ Dreamina ~2,600 credits · เก็บ prompt ที่เวิร์คไว้ใช้ต่อ ไม่ทิ้ง
