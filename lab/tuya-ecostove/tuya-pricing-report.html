5. เราใช้จริงแค่ไหน vs Tuya คิดเงินเท่าไหร่

Flagship Plan ให้โควต้า 75,000 เครื่อง + 160 ล้าน API calls/เดือน — แต่โครงการเราใช้เพียงเศษเสี้ยว ตารางด้านล่างแสดงว่าเราจ่ายแพงกว่าที่ใช้จริงมากแค่ไหน:

จำนวนเครื่อง API calls/เดือน ใช้โควต้าไป มูลค่าการใช้งานจริง/ปี ต้องจ่าย Flagship/ปี
12 (ปัจจุบัน) ~26,000 0.02% ~70 บาท 850,000 บาท
300 (เป้าหมาย) ~650,000 0.4% ~1,800 บาท 850,000 บาท
Source คำนวณจาก Tuya overage rate: $3.15/ล้าน API calls + $1.24/ล้าน messages — Tuya IoT Core Pricing
สรุป: โครงการ 300 เครื่อง ใช้โควต้าจริงไม่ถึง 1% ของ plan — แต่ Tuya ไม่มี plan ที่เล็กกว่านี้ ต้องจ่าย 850,000 บาท/ปี เต็มจำนวน ไม่ว่าจะใช้ 1 เครื่องหรือ 75,000 เครื่อง

6. ทางเลือก — ระบบ Open-Source (ทำเอง)

สถาปัตยกรรมที่เสนอ

บอร์ดไมโครคอนโทรลเลอร์ + เซนเซอร์ → WiFi (Hotspot) → เซิร์ฟเวอร์รับข้อมูล → ฐานข้อมูล → Dashboard

*(ESP32 + Sensor Modules → WiFi → ThingsBoard/MQTT → Supabase → Dashboard)*

8. ข้อดี-ข้อเสียของแต่ละทาง

Tuya IoT Core (Flagship)

+ Sensor สำเร็จรูป ใช้งานได้ทันที

+ ไม่ต้องเขียน firmware

+ Factory calibrated

- ค่าบริการ ~850,000 บาท/ปี

- ใช้ capacity เพียง 0.4% (300/75,000)

- Vendor lock-in — ผูกกับ Tuya ตลอด

- ไม่มี plan ที่เหมาะกับ 300 เครื่อง

ระบบ Open-Source (ESP32 + ThingsBoard)

+ ค่าใช้จ่ายต่ำ — จ่ายครั้งเดียว

+ ไม่มี vendor lock-in

+ Reproducible — นักวิจัยอื่นทำตามได้

+ อ้างอิงใน paper ได้เต็มที่

+ ปรับแต่ง sensor/firmware ได้ตามต้องการ

- ต้องเขียน firmware ESP32

- ต้อง calibrate sensor เอง

- ใช้เวลาพัฒนา + ประกอบ

9. ผลกระทบต่อระบบเดิม (ถ้าเปลี่ยนเป็น Open-Source)

ส่วนของระบบ ต้องแก้? รายละเอียด ผู้รับผิดชอบ
Dashboard ไม่ อ่านจาก Supabase เหมือนเดิม —
Supabase (DB) ไม่ โครงสร้างเดิมใช้ได้ —
Volunteer Page ไม่ กรอก TVOC/CO manual เหมือนเดิม —
LINE OA ไม่ สรุปข้อมูลเหมือนเดิม —
Admin System ไม่ ทุกอย่างเหมือนเดิม —
ตัวดึงข้อมูล *(sync.js)* แก้ เปลี่ยนจากดึงผ่าน Tuya → รับจากเซิร์ฟเวอร์ของเราเอง ทีมพัฒนา
โปรแกรมในตัวเครื่อง *(Firmware)* ใหม่ เขียนโปรแกรมให้บอร์ดอ่านค่าเซนเซอร์ + ส่งข้อมูลผ่าน WiFi ทีมพัฒนา
เซิร์ฟเวอร์รับข้อมูล *(ThingsBoard)* ใหม่ ติดตั้งระบบรับ-เก็บข้อมูลจากเครื่องวัดทั้ง 300 ตัว ทีมพัฒนา
ออกแบบตัวเครื่อง ใหม่ เลือกเซนเซอร์, ออกแบบแผงวงจร, เคส ร่วมกัน
ปรับเทียบความแม่นยำ *(Calibration)* ใหม่ เทียบค่าเซนเซอร์กับเครื่องมือมาตรฐาน เพื่อใช้อ้างอิงใน paper ร่วมกัน
จัดซื้ออุปกรณ์ ใหม่ สั่งซื้อบอร์ด, เซนเซอร์, เคส, แบตเตอรี่ 300 ชุด อาจารย์/ทีมวิจัย
ประกอบเครื่อง 300 ตัว ใหม่ บัดกรี, ประกอบ, ลงโปรแกรม, ทดสอบทีละตัว อาจารย์/ทีมวิจัย
คู่มืออาสา แก้ อัพเดทขั้นตอนเชื่อมต่อ + วิธีใช้เครื่องใหม่ ร่วมกัน
ทีมพัฒนา = ฝั่ง software/firmware อาจารย์/ทีมวิจัย = จัดซื้อ + ประกอบ + ภาคสนาม ร่วมกัน = ต้องตัดสินใจ/ทำร่วม
