# ห้ามอธิบาย Common Sense ของ Audience

**Rule**: ก่อนใส่คำอธิบายเสริมในเอกสาร → ถาม **"audience ของเอกสารนี้รู้อยู่แล้วไหม?"**
- ถ้ารู้แล้ว → ไม่ต้องอธิบาย (ดู patronizing + ทำให้เอกสารยาวเกิน)
- ถ้าไม่รู้ → อธิบายเต็ม

**Why** (DewS feedback 2026-05-06):
- หนูเขียน "watermark AI มุมซ้ายบน → ครอปออกตอนตัดต่อ (Premiere/CapCut/DaVinci...)"
- DewS แก้: **"อันนี้ไม่จำเป็นต้องบอก เป็นคอมม่อนเซ้นท์คนทำงานอยู่แล้ว"**
- Oh ทำงานในวงการที่เกี่ยวกับวิดีโอ → รู้อยู่แล้วว่าครอปขอบใน Premiere ทำยังไง
- ถ้าอธิบาย common sense → เหมือนสอนคนใช้คอมว่า "คลิกเมาส์คือกดปุ่มซ้าย"

**Tension กับ rule "ห้ามใช้ jargon"**:
- 2 rules นี้ดูขัดกัน แต่จริงๆ complementary
- **ห้ามใช้ jargon** = ใช้คำที่ audience เข้าใจได้
- **ห้ามอธิบาย common sense** = ไม่อธิบายสิ่งที่ audience รู้อยู่แล้ว
- **Both rules ต้องคิดถึง audience จริงๆ** — รู้อะไร ไม่รู้อะไร

**How to apply**:
- เวลาเขียนเอกสาร → กำหนด "skill assumptions" ของ audience ก่อน
- ตัวอย่าง Oh's profile:
  - ✅ เข้าใจ video editing common sense (ครอป, ตัดต่อ, file format)
  - ❌ ไม่เข้าใจ AI prompting วิธี (ของใหม่สำหรับเขา)
  - ✅ มี vocab พื้นฐาน 3D/preview (ผ่านงาน Maya เกี่ยวข้อง)
  - ❌ ไม่รู้ cinematography vocab ลึก (ARRI, Cooke, etc.)
- ใส่คำอธิบายเฉพาะส่วนที่เกินกว่า audience profile

**Test before adding explanation**:
1. คนกลุ่ม audience นี้ทำงานในวงการที่เกี่ยวกับสิ่งนี้ไหม?
2. ถ้าใช่ → เป็นความรู้พื้นฐานของวงการเขาหรือไม่?
3. ถ้าใช่ → **ลบคำอธิบาย**
4. ถ้าไม่แน่ใจ → ถามคนที่รู้ audience ดีกว่า (เช่น DewS รู้จัก Oh)
