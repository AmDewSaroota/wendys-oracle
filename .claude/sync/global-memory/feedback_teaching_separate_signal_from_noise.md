# แยก "หลักการสากล" ออกจาก "กฎของ project ปัจจุบัน"

**Rule**: เวลาเขียนเอกสารสอน/ส่งต่อให้คนนอก project — ต้อง **แยกชัด** ระหว่าง:
- **Universal** = หลักการของ tool/workflow (ใช้กับงานอื่นได้)
- **Project-specific** = decisions ของ DewS สำหรับงานนี้ (อย่ายัดเป็นกฎ)

**Why**:
- DewS feedback (2026-05-06): "ห้ามมี BGM เด็ดขาด ไม่ต้องเน้นขนาดนั้น เพราะพี่เค้าอาจจะไปทำงานอื่น"
- Oh (และคนอื่นที่อ่าน) อาจเอาไปทำ MV / ads / สารคดี — ไม่ใช่ dragon cinematic
- ถ้าหนูยัดกฎ project ของ DewS เป็นกฎทั่วไป → คนอ่านเข้าใจผิด → ทำงานติดข้อจำกัดที่ไม่จำเป็น

**Examples ที่ต้องระวัง**:
| Project-specific (อย่ายัดเป็นกฎ) | Universal (ใส่ได้) |
|----------------------------------|---------------------|
| "ห้ามมี BGM" (เพราะ game cinematic) | "ระบุ sound direction ตาม project" |
| "ใช้ภาษาไทยใน @ref" (เพราะ DewS อ่านจีนไม่ออก) | "ใช้ชื่อ ref ที่อ่านปุ๊บรู้ทันที" |
| "Dragon character sheet" naming | "ใช้ role name คงเส้นคงวาตลอด project" |

**How to apply**:
- เขียน universal rule ก่อน
- ถ้าจะใส่ตัวอย่าง project-specific → wrap ในกล่อง 💡 + บอกชัดว่า "ของ DewS เลือกแบบนี้สำหรับ Fortal — งานอื่นปรับได้"
- ห้ามใช้คำเด็ดขาด ("เด็ดขาด", "ห้าม", "ตายตัว") กับกฎที่จริงๆ คือ design choice ของ project นี้
- Test: ถ้าคนทำ MV/ads/สารคดี อ่านแล้วยังใช้คำสอนนี้ได้ → ผ่าน
